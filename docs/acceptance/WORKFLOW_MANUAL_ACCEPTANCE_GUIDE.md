## 4. 这几个“继续”含义不同

| 操作 | 应使用的入口 | 预期身份与状态 |
| --- | --- | --- |
| 从初始状态重跑 | 顶部 **运行** | 新 Thread、新 Run；从初始 State 开始 |
| 等待人填写 | 节点气泡 **提交回应并继续**，或多等待批量提交 | 恢复原 Thread 的准确 interrupt/task；不会另开独立业务会话 |
| 调试断点继续 | **继续调试断点** | 原检查点继续，无业务表单回答 |
| 成功会话的下一轮 | **会话与历史操作 → 下一轮输入 → 使用当前运行输入继续下一轮** | 同 Thread、新一轮 Run，继承 State 与累计额度；此按钮读取“下一轮输入”区域 |
| 故障安全恢复 | **尝试从检查点继续**，仅在可安全恢复时 | 沿用原执行版本/检查点；不是用新草稿替换旧失败代码 |
| 历史修正/试算 | **预览新的分支副本 → 确认执行此分支** | 新 Thread、新 Run，保留来源关系；源历史只读 |

每例可展开 **当前运行与检查点身份**，记录 Run、Thread、Checkpoint；子图再记录图路径/namespace，重复节点再记录 task/执行次数。列表中的执行序号不等于重试次数；并行任务也不保证固定完成顺序。

## 6. 逐项人工验收

以下除 M00、M20、M21 外均使用学生主账号、真实执行、Local acceptance。每例“通过门槛”同时也是失败判据：结果不符、过程缺证或权限越界，记录失败/阻塞，不代签。

### M00 · 访客、登录与演示角色

**操作**：独立无痕窗口不登录访问 `/courses`，再访问 `/workflows`；按页面登录引导登录学生账号。主窗口已登录可直接进入。查看账户菜单，确认使用的是 Local 学生。

**通过门槛**：公开课程允许浏览；画布需要认证并保留明确返回目的地；登录后能打开本文流程。访客不启动 Assistant 对话或生成学习进度。

**对应特性**：产品认证、渐进登录、用户隔离。**LangGraph 对应**：无原生身份功能；由 EduFlow 在进入图执行前完成认证，后续 Thread/Store 使用服务端身份。登录成功不是图执行已通过。

### M01 · 一次人机等待：差旅报销金额核算

**操作**：打开 [差旅报销金额核算](http://127.0.0.1:5173/workflows/d5de21f1-9ba5-4b9f-b181-b22f77a147db)，校验并运行。点“汇总差旅费用”的等待气泡，在 **住宿费用（元）** 输入 `300`，点 **提交回应并继续**。查看最终输出。再返回流程编辑、新建一次运行，输入 `0`。

**通过门槛**：第一轮住宿 300、交通 200、合计 500；第二轮合计 200，数字 0 不能被当成“未填写”。等待期间刷新页面仍能找回同一任务，提交后只有一次有效消费。

**对应特性**：P3 普通节点可中断、Schema 表单、恢复关联、P6 跨刷新观察。**LangGraph 对应**：节点内 `interrupt()`、checkpoint 与 `Command(resume=...)`。表单校验、有效期和请求幂等由 EduFlow 提供。

### M02 · 静态并行与 all 汇合

**操作**：打开 [P3 · 并行费用汇总](http://127.0.0.1:5173/workflows/a13d878d-1831-4fd2-83a7-74673c94e364)，运行，分别查看交通、住宿气泡的读取和写入，再看“等待两项费用”及“汇总费用”。

**通过门槛**：交通 `a=300`、住宿 `b=500`；两项完成后才汇总，`total=800`，汇总仅执行一次。查看步骤/事件确认两条分支都真实执行；不能只凭画布两根线或耗时变短判定并行成功。

**对应特性**：P3 fork/join 与分支执行可观察性。**LangGraph 对应**：StateGraph 分支、Pregel super-step 与同步汇合；EduFlow 将显式 fork/join 配置编译为底层调度。此例证明 all，不单独证明 any 或不同长度分支的全部组合。

### M03 · Send 动态任务和 Reducer

**操作**：打开 [P3 · 动态批量汇总](http://127.0.0.1:5173/workflows/2241715a-10d9-4a6f-878a-08cd364c8f4a)，运行，点击动态处理节点，切换 **执行次数** 查看三个 task 的输入输出；在 State/最终输出检查结果。

### M04 · 并行、子图、多等待的核心关系

**操作**：打开 [P3 · 双部门确认与子图](http://127.0.0.1:5173/workflows/54007e48-10f4-4ea2-afbc-928f3ad3945f)，运行。用执行面板的 **定位：…** 或气泡的 **选择待回应任务** 找到主图与子图各一个待回应任务。先只给交通项的 **确认金额** 填 `300` 并提交；刷新页面，点主图子图气泡的 **进入回应：请确认住宿费用**，在子图的 **确认金额** 填 `500` 提交。另开新运行，切换待回应任务给两项分别填 300/500，使用 **提交全部已填写回应并继续**。

**通过门槛**：第一次部分回应后不会结束，也不会丢失另一等待；已接受项不重新提问/重复计入。最终两轮都是 800。批量按钮不能把空白任务默认为 0；必须都填写。主图与子图 task、namespace 不串线。

**讲解顺序**：并行决定“有多个独立待执行任务”；子图决定“任务属于哪个嵌套图及状态范围”；interrupt 决定“哪个具体任务暂停”；checkpoint 保存三者关系；恢复必须按准确身份投递，不能广播回答给所有同名节点。

**对应特性**：P3 多中断队列、部分/批量回应、嵌套图定位；P5/P6 精确历史和刷新恢复。**LangGraph 对应**：并行 Pregel task、子图 namespace、原生 interrupt/resume map、持久化 checkpoint。此例使用 per-invocation 子图；不代表 per-thread 并发 Send 可任意组合。stateless 子图不支持等待，受控拒绝才是正确行为。

**操作**：打开 [人工演示 · 条件分支与有界循环](http://127.0.0.1:5173/workflows/347e75b3-08de-42f8-ad12-bb5e3eb51b51)，执行区 **累计到几** 填 `3`，运行；查看“是否继续累计”和“每次增加一”的多次执行。再新运行填 `0`。

**通过门槛**：3 对应 `total=3`；0 直接结束，`total=0`。循环重复节点有独立执行记录，不能把后一次覆盖成唯一一次。副本超过输入上限 10 应被 Schema 拒绝；图递归与执行次数限制是另一层保护。

**对应特性**：P3 条件边、循环、预算。**LangGraph 对应**：`add_conditional_edges`、图重入及 recursion limit；具体输入范围和累计执行预算是 EduFlow 策略。

等待独立 watchdog 将失联运行收敛为故障（通常需约 30–40 秒，以实际租约和页面状态为准）。记录 `WORKER_LOST`、原 Thread/CP 和已提交状态，再恢复 Worker：

```sh
pnpm workflow:control start worker
```

回原运行，若出现 **尝试从检查点继续**，点击后等待约 15 秒；目标输出 `total=7`。如已错过 15 秒、停止前已完成，则本次没有注入成功，不能签“故障恢复通过”；恢复服务后可重新选择一轮。结束时确认 Worker 已恢复，再执行 M02 检查正常服务。

**通过门槛**：独立 watchdog 收敛失联，无无限 running；同版本安全检查点可恢复，旧 Worker 迟到结果不覆盖新执行。不适用检查点必须说明原因，不能强行重跑未知外部写。本轮新示例预留第二次显式尝试，自动重试分类为空，不以后台盲重试伪装人工恢复。

**生命周期补充**：当前列表保留最近 20 个 Run，旧历史受保留策略管理；可在副本做 21 次无模型运行观察，不删除生产/原有学习数据。7 天会话过期、凭据轮换、云端回滚、Sandbox 隔离攻击与限额压力不适合现场快速证明，使用下一节的既有专项证据，或另开受控环境复验。**本次启动准备没有注入 Worker 故障**，此项待人工实际执行。

**对应特性**：P6 独立 watchdog、租约 fencing、恢复、运维可观测性。**LangGraph 对应**：官方 checkpointer + sync durability 提供图状态恢复基础；PGMQ、Worker 心跳、watchdog、版本匹配、fencing 和部署健康检查为 EduFlow 基础设施，不能宣传成原生自动部署或任意外部副作用 exactly-once。

## 8. 演示时如何解释 LangGraph 架构

当前主链是：**React Flow 编辑 Definition V2 → 认证 API → Python Compiler → 数据库队列/Worker → 官方 LangGraph StateGraph → 官方 PostgreSQL Checkpointer/Store → 产品执行事件与页面结果**。

| 能力 | LangGraph 原生基础 | EduFlow 实现与负责的边界 | 看哪个案例 |
| --- | --- | --- | --- |
| 图与并行 | StateGraph、edge、conditional edge、Pregel | Definition 编译、显式 fork/join、Schema/预算 | M02、M05 |
| 动态调度 | Send、Command | 可视化配置、合约校验、身份与并发限制 | M03、M06 |
| 共享状态 | Reducer、Overwrite、channel 更新 | 可信目录、类型验证、冲突规则 | M12、M17 |
| 嵌套执行 | 子图、task、checkpoint namespace | 主子图绑定、路径导航、persistence 组合规则 | M04、M11、M14 |
| 人工介入 | interrupt、Command.resume、静态断点 | 表单、待办索引、部分/批量回应、幂等/有效期 | M01、M04、M07 |
| 持久化 | AsyncPostgresSaver、sync durability | Run/Step/事件事务、版本/owner/env、租约恢复 | M15、M21 |
| 计算策略 | RetryPolicy、CachePolicy、error_handler | 隔离函数、注册版本、attempt 账、外部写安全边界 | M08–M10 |
| 流 | astream values/custom、get_stream_writer | 模型官方 SDK 流、步骤归属、脱敏、完成保护、UI | M14、M18 |
| 记忆/历史 | AsyncPostgresStore、get_state/history、bulk_update_state | TTL/CAS、命名空间、预览与显式确认、事务发布 | M16、M17 |
| 安全与运维 | 可持久化图的执行基础 | 认证、RLS、Vault、Docker/云端 Sandbox、PGMQ、watchdog、Vercel/Supabase 部署 | M00、M13、M20、M21 |

## 10. 现场问题处理与恢复

- **只有历史可看，按钮灰色**：点 **返回流程编辑**；历史是冻结快照。不要复制旧 Run 的输入去冒充恢复。
- **找不到等待节点**：执行面板 **定位：…**、**选择待回应任务**；必要时进入子图。查看 task 身份，不按同名节点猜。
- **旧历史不可恢复**：旧执行指纹与当前版本不兼容时允许拒绝；保存当前定义并新运行，原历史保留。改代码后也要新运行。
- **缓存第一次就命中**：准备预检可能留下热缓存；等 TTL 过期再比冷/热。不要重启整个系统只为演示缓存。
- **模型慢或失败**：记录原 Run、供应商错误/完成原因；先确认预算、网络和密钥绑定，不重复点击运行。没有 delta 不代表免费。
- **Teacher/Admin 看不到这些流程**：本文流程属于学生，跨账号不可读是预期；切回主账号，不提升权限绕过。
- **分支按钮不可用**：先读具体禁用原因；检查是否主图、检查点是否仍可执行、版本是否兼容、是否完成外部影响确认。已有分支预览禁用说明属于已知易用性边界，不能强行重复发请求。
- **前端在，运行服务失联**：确认本机 Docker/Supabase 可用。只需恢复现有工作流服务时，在仓库执行下面命令；它复用已有本地配置。`/health` 裸访问返回 401 是内部身份保护，不能单据此判服务坏了。

```sh
pnpm workflow:control restart
```

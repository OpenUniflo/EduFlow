# Micro Learning and Evidence

Authoring follows the canonical [Teaching Pattern Library V1](TEACHING_PATTERN_LIBRARY.md): instructional need → pattern → cognitive strategy → existing runtime → feedback → validation. Patterns are not runtime types. Micro defaults to bounded interactions without long-text input; teaching and Summary remain separate from system navigation. Use that specification for selection rules, anti-patterns, scientific rationale and addition gates.

EduFlow's learner loop is persisted and data driven:

`Knowledge -> MicroLearningPath -> MicroUnit -> MicroStep -> Evidence -> UserKnowledgeState`

`MicroLearningPath` is a reusable or course-specific learning experience for one Knowledge. It is not a personal learning plan. Required Units determine path completion; progress stores the current Unit and Step so reopening resumes from the database.

After a Path is complete, “重新复习” starts at the first Step of the first required Unit and advances through the required review sequence in the current page. Review answers use the same deterministic native/H5P result semantics, but the review branch never calls start/complete progress APIs, refreshes learner state, or emits another completion Evidence record. The durable completed Path, timestamps, Evidence, and monotonic Knowledge state therefore remain unchanged; anonymous review remains page-local and disposable.

Native `choice`, `multiple-choice`, `fill-blank`, `categorize`, `ordering`, `trace`, `mini-workflow`, `structure-builder`, `parameter-lab`, and `matrix-tensor` interactions carry their content and deterministic evaluation data in the Step contract. Shared renderers own interaction state, feedback, retry, disabled, focus, and completion behavior; course content does not embed arbitrary renderer-specific HTML. Ordering uses dnd-kit pointer/touch drag, insertion feedback, animated displacement, and sortable keyboard controls; Mini Workflow is a small React Flow projection of a linear expected structure and does not create a second Workflow domain.

`structure-builder`, `parameter-lab`, and `matrix-tensor` explicitly support `explore` and `challenge`. Explore accepts a valid manipulation to teach mechanism without claiming a unique answer. Challenge validates the published target edges, numeric range, or target tensor. Legacy definitions remain supported. The four Micro V2 reference paths use the richer mechanism contracts below; the simple legacy numeric controls are not the V2 instructional examples. H5P remains a compatible adapter rather than the default authoring dependency.

H5P is an external `MicroStep` adapter. EduFlow uses the MIT-licensed `h5p-standalone` player because it can load validated, extracted H5P packages from object storage without adding a server-side H5P platform or a new Vercel entrypoint. `h5p_contents` owns stable metadata and `micro-h5p/{contentId}/{revision}/...` owns extracted assets. The public-read bucket is required for relative library assets; it has no learner or authenticated write policy. A controlled service-role importer validates package size, paths, the supported main-library allowlist, executable HTML/SVG patterns, external asset URLs, metadata/version agreement, and an immutable package checksum before publishing metadata.

`EduFlowH5PAdapter` maps xAPI `answered`, `completed`, `passed`, and `failed` statements to `{ completed, success, score, maxScore }`. `/api/micro` then revalidates the Published Path → Unit → Step relationship, exact `contentRef`, published content metadata, result shape, score range, and explicit `completed` or `passed` policy before normal progress writes. Opening content never completes a Step. Duplicate events are harmless because Step completion, progress upserts, and Evidence uniqueness are idempotent.

This boundary is intentionally learning-grade, not an exam anti-cheat system: a trusted browser runtime reports the H5P result, while the server prevents unrelated Step completion and malformed or mismatched payloads. A full H5P server/editor and signed assessment statements are outside the current prototype.

Knowledge state transitions are monotonic: starting learning reaches `learning`, completing a required Learn Path reaches `learned`, starting a related Assignment reaches `practicing`, and the mastery policy may reach `mastered`.

The MVP mastery policy is intentionally conservative. Every required Learn Path must be completed and every explicitly required Assignment must be `accepted`. If no Assignment is explicitly required, path completion remains `learned`. `submitted` is never acceptance or mastery.

Evidence is owned by EduFlow and idempotent by `(user, knowledge, event type, source entity)`. It records `micro_path_completed`, `assignment_accepted`, and `workflow_passed` with source identity, outcome, context, and timestamp. This is intentionally shaped for future xAPI export without making xAPI the canonical internal model.

Golden Agent, Workflow, and Failure Recovery paths are seeded/imported into canonical tables and are always read through `/api/micro`. TypeScript Demo providers remain local fixtures only and are not consulted by the production composition root.

## Micro V2 teaching and runtime contract

A published reference teaches the problem and minimum prerequisite explanation before manipulation, shows a worked mechanism, explains the observed result, offers a changed-scenario practice, gives causal retry feedback, and ends with explicit learning outcomes. Existing `MicroStep.kind` expresses these roles: `explanation`, `interaction`, `feedback`, `application`, and `summary`. No rigid eight-page requirement or new teaching-stage table exists. Choice remains a recall/check tool; Fill Blank remains supported for genuinely short answers. Neither is the core of these references.

Three additional native content variants encode information the old primitives cannot represent:

- `flow-execution`: bounded authored nodes, directed candidate edges, initial connections, required connections, and a coherent execution event trace. React Flow owns handles, connect/delete/select and rendering; the shared pure runtime validates transitions and stops on missing data connections. Node/message labels and explanations come from content. It does not execute external tools or become the Workflow or Navigation authority. Challenge completion revalidates the exact required connection set and complete trace; Explore requires a valid executed trace without a unique editable topology.
- `simulation`: a bounded parameter and a `quadratic-descent` computation model with curvature, optimum, initial parameter, horizon, and an outcome target. Shared calculation derives gradient, parameter delta, trajectory, loss, oscillation, and convergence behavior. Challenge grades calculated final loss and maximum growth, never a hand-selected learning-rate interval. Numeric bounds prevent nonfinite supported trajectories. Additional computation families require explicit schemas and calculation tests; arbitrary code/eval is forbidden.
- `data-transform`: tokenized corpus, explicit vocabulary, and a left/right window radius. Directed center/context events are derived from the corpus without crossing sentences. Each valid manual cell operation consumes one actual event; wrong cells leave state unchanged and explain row, column, and distance. Explore can Step/Play the process; Challenge requires manual event counting. The server recomputes the resulting cells and event count.

`src/shared/learning/microMechanisms.ts` contains schema validation, calculations, grading, and the small timeline reducer/scheduler. `src/features/learning/micro/runtime` owns React projections only. One cancellable timeline supports Step, Play, Pause and Reset; cleanup prevents late ticks after pause/reset/unmount. Changing the input parameter or graph connections resets the derived execution trace. Motion conveys the current computation point, event/cell update and spatial placement; reduced motion suppresses transforms and animated flow paths. Dnd-kit owns drag sensors, sortable displacement and overlay/drop behavior; category placement also has a click/keyboard alternative. Illegal drops preserve the original answer. No animation component writes progress, evidence, attempts, mastery or navigation.

Learner and authoring previews use the same `NativeInteraction` renderer. Authoring creates proposal content and still requires deterministic validation, preview, confirmation and Publish. Content identities are not normalized from presentation text. Both malformed schema validation and grading fail safely. The existing JSONB constraint is extended through a forward migration; no learning-state schema is added. `scripts/verify-micro-v2.ts` checks SQL/TypeScript malformed-input parity and exact idempotent reference replay against explicitly Local Supabase.

## Review navigation and mathematical teaching content

Back navigation is review-only and never rolls back formal learning progress. The existing `reviewCursor` selects a temporary Step independently of repository progress and the completed-feedback `pinned` position. The current formal Step remains mounted, paused and hidden during review so its in-memory answer, Flow connections, timeline and H5P state survive returning. Review uses a separate transient interaction; checking, replaying and resetting it never calls `completeStep`, refreshes learner state or persists a review result. Review navigation is available without solving old practice again, including the final Summary of completed paths. Refresh/navigation away discards the transient review and unsaved interaction, then resumes database progress; there is no new review persistence model.

`MicroStep.body` remains text. Explicit `\( … \)` and `\[ … \]` opt into inline and block KaTeX respectively; paragraphs/newlines remain text and raw HTML is escaped. Unsupported TeX falls back to readable source. Rendering uses `trust:false`, fresh macros and bounded expansion/size. Block formulas scroll within their own region on small screens; authored equations should still be divided into meaningful calculation steps. No Markdown stack or rich-content DSL is introduced.

Explain/Summary may reuse an existing mechanism interaction as a demonstration: Flow connection editing, simulation parameter editing and matrix manual entry are disabled, while the common timeline supports step/play/reset. Explore and Practice keep their existing grading and manipulation semantics. Demonstrations are original reviewed content in the same database-backed Step, not runtime course-ID branches or browser fixture fallbacks.

Flow, Simulation and Data Transformation return deterministic `reason` and factual state (edge/execution position, trajectory/behavior, or mismatched cell). Optional `interaction.teaching.feedback` maps these reasons to authored explanations; `interaction.teaching.explanation` supplies deeper mechanism reasoning for “为什么？”. Generic operation prompts remain runtime copy. The existing Assistant receives validated Course/Knowledge/Path/Unit/Step identities; this round does not add answer payload authority, a Tutor endpoint, or LLM grading. “为什么？” is immediate authored explanation, not a duplicate success message or an AI claim.

The content-only migration `20260905162819_micro_v2_teaching_content.sql` updates only existing official Reference Steps and content revision. It changes no tables/functions/schema, identities, ordering, evidence or learner records. Generate with the existing generator's `--content-only` option; Local/Hosted must use the same verified SQL. The local course sync replays it after older content migrations.

## Lesson content production and independent instructional review

Lesson 1 of `ai-agents-in-depth` validated this production sequence: inspect canonical Knowledge definitions, factual prerequisites, curriculum order and actual Material pages; state a bounded Lesson outcome; author explanatory content; obtain independent Teacher and Student review; revise and reread the complete lesson; conduct closed-book recall; then publish content data and repeat learning in the real UI. The Author edits content, the Teacher checks correctness/sequence/grounding, and the Student records understanding and confusion. Reviewers do not edit the material they approve. Simulated Student results and browser execution are evidence with explicit limits, not a human learning study or proof of engineering ability.

Use one main cognitive objective per Micro, with enough explanation and a worked example before asking for an answer. A question checks an explanation; it does not replace it. A process benefits from an existing mechanism demonstration: Lesson 1's two-round feedback trace and missing-return comparison made the causal role of observation visible. Definitions and comparisons can remain text. Neither every Knowledge nor every Explain requires an interaction or animation. Review replays teaching without becoming assessment or another completion Evidence event.

Introduce necessary terms in the learner's language and connect them through one concrete task before adding more roles. Use plausible misconceptions in checks and a changed task in transfer questions. Distinguish decision from execution, task records from external facts, predefined branches from model-selected actions, and isolation from correctness. Closed-book questions should test these distinctions in the learner's own words; correct clicks alone are insufficient.

Ground each central conclusion in actual MaterialSegments and keep the primary locator useful for the current explanation. PDF page numbers must refer to the reader's actual pages, with printed-page offsets recorded separately in the source audit. Preserve cross-section supporting mappings, mark teaching adaptations, and attribute the source without claiming a new license. An unsupported statement remains a source gap until resolved; an external supplement must be identified explicitly. Lesson 1 uses 李博杰's book, v1.4, 2026-08-13, and adds paraphrases/marked teaching examples rather than redistributing source PDF/image assets.

Curriculum order is a Course projection over stable Knowledge identities. A teaching adjustment belongs there, with a reason; it does not change Global Knowledge identity or manufacture prerequisite facts. Lesson 1 retained all ten Knowledge identities and their existing order, and bridged its out-of-Course A01 prerequisite in the explanation using the book. Its outcome is an explanatory mental model, not independent Goal/Outcome lifecycle data or a mastery claim.

Validate authored interactions with the existing native validator and check the actual desktop/narrow UI. Schema-valid coordinates do not establish readable diagrams: inspect Fit, active states, return-edge geometry, scrolling, footer controls, and actual pointer/keyboard operations. Test the complete transition from Summary through the Course graph and Material reader; document the visible steps, including chapter expansion. Real navigation friction belongs in the acceptance ledger even when it is an existing runtime follow-up.

The reviewed Lesson 1 source is `data/gold-courses/ai-agents-in-depth-lesson1.json`; primary/supporting source fields are offline metadata. `scripts/dev/generate-agent-lesson1-migration.ts` reuses native validation and emits the CLI-created `20260906161347_agent_lesson1_teaching_content.sql` with `--content-only`. It publishes ten new Course Learn Paths, ten Units and 52 Steps through the existing database/API. This is initial-publication tooling: later published revisions require a new forward migration and appropriate revision handling, not editing migration history. If Course definitions are bootstrapped separately after migrations, replay this content SQL after that Course exists. Shared Hosted rollout remains incremental and compares complete learning-history snapshots before and after applying the reviewed SQL.

## Completion context and instructional continuation

Micro completed = `learned`; `learned != mastered`. Existing stronger mastery evidence may still satisfy the unchanged mastery policy. Teaching prerequisites accept `learned | practicing | mastered`, not `explore | learning`. Course Path/Graph and Navigation share the pure teaching policy. Only factual edges between Course-route Knowledge gate the Course; external Knowledge facts are retained without creating invisible entry requirements.

One Micro Experience supports optional Course context. Historical `scope`, `course_id` and course-first fallback remain compatibility storage, with physical cleanup deferred to #32. Micro body teaches through Summary; the system shell resolves post-Micro context. The completion resolver projects only real Material coverage/Segments, Assignment coverage and Navigation next Knowledge. Practice is secondary and does not block teaching continuation; future competency remediation and Attempt/Performance work remain #22.

Next Micro uses `/learn/micro/:knowledgeId` with optional `courseId`, never a hardcoded next Path identity. Material links reuse coverage-role priority and exact Segment resolution. Reader `location.state.returnTo` returns to the originating Micro; `returnState` preserves that Micro's source, and Segment query replacements preserve location state. Completion/reopen reads persisted progress; Review stays local and does not repeat formal evidence.

The Lesson 1 cleanup removes only ten Summary navigation suffixes. Generator `--content-only --navigation-only` updates those existing Step bodies, checks ownership and curriculum order, and does not alter schema, Knowledge, curriculum, other teaching fields or learner history.

## Formal Micro interaction observations

The formal Step submission now records a numbered `micro_step_attempts` fact whether correct or incorrect. That record **is** the interaction Evidence, not a duplicate `knowledge_evidence` completion event. Existing `knowledge_evidence` continues to hold its original path/Assignment/Workflow completion facts and is not trusted as criterion-performance input. The legacy Assignment-only `learning_attempts`, `performance_results` and `learning_events` remain unchanged.

The server evaluates the actual response against the loaded native definition. Its service-only transaction checks current content against the evaluated snapshot, locks content during recording, validates Course ownership/coverage and instructional prerequisites, freezes active evidence-producing Criterion references, records the attempt, and calls the existing completion/mastery transaction only when accepted. Wrong answers persist without completing the Step. Instruction and explore interactions are `observed`; H5P xAPI completion is `reported_completion`, explicitly a client report, and neither manufactures criterion attainment. The mapping's `instruction`/`evidence` purpose remains separate from runtime interaction type.

Attempts store user, optional Course, Knowledge, Path/Unit/Step IDs, path revision, evaluated-content hash, actual response, observed outcome, accepted-completion flag, optional validated decision identity and database timestamp/sequence. `attempt_number - 1` is the retry count for that user/Path/Step; a browser-measured visible duration is explicitly `client_duration_ms`, never an authority or estimator input. No hint count, success probability or expected duration is invented.

A browser submission has one UUID retained across transport failure; a received wrong answer permits a new attempt key. Conflicting reuse is rejected; identical concurrent retries produce one fact. Legacy callers without a key receive a deterministic request-content key rather than silently duplicating facts. Replaying an already completed Step and presentation-local Review do not create new formal performance. Anonymous answers remain ephemeral.

Criteria and attempt identities survive content history. Publishing retains Criterion mappings only for stable Step/Knowledge identity with unchanged kind/interaction; changed teaching checks need explicit remapping instead of inheriting an unreviewed evaluation meaning. Attempt source identities deliberately remain historical references rather than cascading through content replacement. Criterion definition edits require a new version; old evidence retains the old version.

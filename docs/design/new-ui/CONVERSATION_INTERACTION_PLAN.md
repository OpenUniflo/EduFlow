# 对话交互改进：实施方案

日期：2026-11-07 · 状态：方案待确认，尚未开始实现 · 范围：桌面端首页对话、小练习形态、对话记录、课程路线

交互原型（第二版，以它为准）：https://claude.ai/artifact/EF2e5mieFohoVUWcuyd5QL

前置文档：[CONVERSATION_MAINLINE_PLAN.md](CONVERSATION_MAINLINE_PLAN.md)。本方案在其阶段 4 之后、阶段 5 之前执行。

## 1. 要解决的问题

下表的数据来自 2026-11-06 用真实鼠标和滚轮的实测。

| 问题 | 实测 | 根因 |
|---|---|---|
| 只有中间一列能滚动 | 左右边距、顶部、输入区滚动距离都是 0 | 滚动区只有 760px 宽（`.ef-home-timeline`） |
| 卡片上滚动失败，卡片像在动 | 1280×720 下卡片内层可滚 96px，外层不动 | 卡片内嵌滚动区并设了 `overscroll-behavior: contain`（[assistantCards.css:213](../../../src/features/assistant/cards/assistantCards.css)） |
| 卡片空白太大 | 按钮上方空 84px、下方空 88px，对话底部多留 240px | 反馈区常驻占位，旧的底部内边距未被覆盖（[home.css:2434](../../../src/features/home/home.css)） |
| 全屏没有过渡 | 约 57ms 跳到新路由，对话被卸载 | 全屏是路由跳转（[AssistantCardView.tsx:222](../../../src/features/assistant/cards/AssistantCardView.tsx)） |
| 开始后不能切换形态 | 展开时只有“收起” | 卡片、侧边、全屏是三个独立实例 |
| 切换后答案丢失 | 收起再展开、进入全屏后，选择都被清空 | 答案是 `MicroStepPanel` 的本地状态，切换会卸载组件 |
| 同一练习开出两份 | 右侧面板开着时再点卡片，出现两个并排实例 | 同上，没有统一的打开状态 |
| 卡片标题被遮 | 1280×720 下卡片顶部约 70px 被标题区遮住 | 推测是贴底逻辑盖过卡片定位，实现时确认 |
| 对话记录放错、显示不全 | 在“我的”面板里，只显示前 8 条 | [MyPanel.tsx:94](../../../src/features/home/MyPanel.tsx) |
| 回复时滚动突兀，不能停止 | 回复结束时一次跳 362px；输入框被禁用 | 观察器加定时器定位；未接 `stop()` |
| 路线章节割裂 | 只展开当前章，其他章折叠成列表 | [CourseRoutePanel.tsx:33](../../../src/features/course/path/CourseRoutePanel.tsx) 只传当前章 |

其他小问题并入对应阶段：日期写死“今天”、“回到最新”挤动布局、键盘不能滚动、面板没有过渡、“我的”按钮跳位置、重复的“继续”入口、“为什么？”内容重复、错误文案。

## 2. 技术选择

**结论：不新增运行依赖，也不需要数据库迁移。** 新增能力全部用已有依赖或浏览器原生能力实现。

| 需求 | 选择 | 来源 | 不选的方案及原因 |
|---|---|---|---|
| 整页滚动、输入框吸底 | CSS `position: sticky`、原生滚动 | 浏览器 | 无需库 |
| 贴底和新消息定位 | 一个小 Hook，复用浏览器的滚动锚定 | 浏览器 | `use-stick-to-bottom`：它的模型是贴底跟随，我们要的是把用户消息定位到顶部，用了仍要写定位逻辑 |
| 长列表 | 不做虚拟化 | — | `react-virtuoso`：接口最多返回 200 条消息，课程节点约 100 个，不值得多一个依赖；实测有问题再用 CSS `content-visibility` |
| 形态切换动画 | `motion` 的 `animate()`、`useReducedMotion` | **已有** `motion` 13.2.0 | `layoutId` 要求元素在同一 React 树上换父节点，与下一行的固定挂载方案不合 |
| 切换时不丢状态 | React `createPortal` 挂到一个固定的 DOM 容器，再移动容器 | **已有** React 19 | `react-reverse-portal`：核心逻辑只有十几行，不值得引入 |
| 沉浸遮罩、Esc、焦点限制 | 原生 `<dialog>.showModal()`、`::backdrop` | 浏览器，项目已在用（[WorkflowDialog.tsx](../../../src/features/workflow/editor/v2/WorkflowDialog.tsx)） | Radix Dialog、`focus-trap`：原生已覆盖 |
| 提示条是否显示、路线当前章 | `IntersectionObserver` | 浏览器 | 无需库 |
| 停止回复 | `useChat().stop()`；服务端 `streamText({ abortSignal })` | **已有** `@ai-sdk/react`、`ai` | 不手写流控制 |
| 路线布局 | `buildWindingRoute`、`CourseRouteView` | **已有**（函数已支持多章） | 不重写布局算法 |
| 日期分组 | `Intl.DateTimeFormat` | 浏览器 | `date-fns`：只需要少量格式 |
| 对话重命名、删除 | `api/assistant.ts` 新增 action，RLS 已允许 | **已有** | 不新增 Vercel Function（上限 12 个） |

如果实现中发现确实需要新依赖，先停下来说明理由，得到确认后再加。

## 3. 关键设计

### 3.1 对话布局

```text
应用
├─ 导航栏
├─ 对话记录栏（可收起）
└─ 主区域
   ├─ 滚动容器（铺满，滚动条贴右）
   │  ├─ 标题栏（sticky，只放对话名）
   │  ├─ 760px 内容栏：文字、卡片、事件行
   │  └─ 输入区（sticky，内含浮动的提示条和“回到最新”）
   ├─ 右侧面板（推开对话，一次一个）
   └─「我的」按钮（位置固定）
```

- 文字和卡片共用左边缘，**所有卡片铺满栏宽**，不再有 480px 的 S 卡片。
- 提示条和“回到最新”都用绝对定位，**显示或隐藏不改变滚动高度**。这是修复闪烁的关键，原型实测切换次数从 179～193 次降到 0。
- 对话中不再显示“晚上好”大标题，首次和欢迎状态继续保留问候。
- 滚动只保留三条规则：首次加载到底部；发送后把用户消息定位到标题栏下方，并用占位撑开；用户手动滚动后不再抢位置。删除 [HomeConversation.tsx](../../../src/features/home/HomeConversation.tsx) 里的 `positionCurrentReply`、观察器和定时器。
- 对话区可获得焦点，支持 PageUp、PageDown、Home、End 和方向键。

### 3.2 小练习：一个实例，三种形态

```text
LearningPage
└─ MicroHost（一直挂载，持有运行中的练习）
   └─ createPortal(<InlineMicro/>, 固定容器)
         固定容器被移动到 → 卡片插槽 / 右侧面板插槽 / <dialog> 插槽
```

- 状态用纯 reducer 管理，可单测：

  ```ts
  type MicroForm = "inline" | "side" | "focus" | "closed";
  type MicroPresence = { pathId: string; knowledgeId: string; courseId?: string; form: MicroForm; returnForm: Exclude<MicroForm, "focus" | "closed"> };
  ```
- 右侧面板 reducer（[rightPanel.ts](../../../src/features/home/rightPanel.ts)）继续保证一次一个面板，`micro` 由 `form === "side"` 决定。
- 因为 React 树位置不变，`MicroStepPanel` 的答案状态不用改造就能保留，同一练习也不会出现两份。
- 过渡：记下容器当前位置，移动容器，再用 `motion` 从旧位置动画到新位置，时长取设计规范的 400ms。开启“减少动态效果”时直接切换。
- 所有形态的标题栏都显示“对话内 / 侧边 / 沉浸”切换。沉浸可按 Esc、点遮罩退出，回到进入前的形态。
- 地址：`/?micro=知识:路径:课程&view=focus`，刷新后恢复。上次选择的形态只存在 `localStorage`，作为个人偏好。
- 默认形态不变：简单小练习在对话内，多单元的默认侧边；沉浸只由用户主动打开。
- 卡片的统一入口：合并 `MicroCard`、`KnowledgeCard`、路线卡片中重复的 `useMicroInline` 和 `scrollCardIntoView`（[AssistantCardView.tsx](../../../src/features/assistant/cards/AssistantCardView.tsx)）。
- `/learn/micro/:id` **保留**，课程页、记录页和各种外部链接仍可直接打开，行动执行（`actionRunId`）和复习逻辑不动。首页不再跳转到这个路由。

### 3.3 对话记录和“我的”

- 对话记录移到首页左侧：新对话、搜索、按日期分组、重命名、删除，可收起。空间不足时随右侧面板自动收起，关闭后恢复。
- 分页：接口现在限制最多 50 条（[assistant.ts](../../../api/assistant.ts)），加基于 `updated_at` 的“加载更多”。搜索只匹配标题，在服务端查询。
- 删除是不可恢复操作，必须二次确认。`learning_attempts.assistant_session_id` 已是 `on delete set null`，学习记录不受影响。
- **有一类对话不能删：** `courses.creation_brief_message_id` 是 `on delete restrict`，对话里的消息生成过个人课程时，数据库会拒绝删除。这时不隐藏错误，直接说明“这个对话创建了一门课程，不能删除”，并保留重命名。
- “我的”只放个人信息，条目都可以点击进入对应对象，不再放对话列表。
- 回来时直接显示上次对话，提示条放下一步，不再用欢迎页挡住历史。这改变了 `deriveHomeView` 中“回来”的定义，首次状态不变。

### 3.4 回复过程

- 回复时输入框可继续输入，发送键变成停止键。Enter 不发送，也不清空草稿。
- 停止时用 `useChat().stop()` 中断，服务端把请求断开转成 `abortSignal`。已生成的部分保留，并标记“已停止回复”。
- 实施时先做一次验证：确认中断后 `parts` 能正确落库，刷新后还在，且不会触发现有的自动重试或回复轮询（[AssistantRuntimeContext.tsx](../../../src/features/assistant/AssistantRuntimeContext.tsx)）。标记优先用现有字段；如确实需要新字段，再加迁移并说明。

### 3.5 课程路线

- [CourseRoutePanel.tsx](../../../src/features/course/path/CourseRoutePanel.tsx) 把**所有章节**传给 `buildWindingRoute`，去掉折叠行。课程页 `CourseLearnerRoutePage` 和首页面板共用这个组件，一起生效。
- 章节牌压在路上，走同一条路径，缩小章节间距（现在是 `ROUTE_CHAPTER_GAP = 92`）。滚动时顶部显示当前章和进度。
- 只保留一个操作卡：默认在当前步骤下方，点其他节点就移到该节点。切换选中不重新计算布局（符合 [AGENTS.md](../../../AGENTS.md) 的展示状态规则）。
- 路线有两种形态，沿用 3.2 的移动方式：侧边、整页（左侧固定课程卡，右侧路线）。
- `buildWindingRoute` 的正弦参数和 `ROUTE_START_CARD_HEIGHT` 可能需要调整，改动限于纯函数和它的测试。
- 打开时定位到当前步骤。“下一步”的来源仍是 `learnerStateService.getNavigation`，不新增判断。
- 约 100 个节点时实测滚动帧率。如有问题，先用 `content-visibility`，不引入虚拟列表。

## 4. 实施阶段

每阶段由 DSH 执行，我用真实鼠标亲自验收，不通过就打回。视口统一测 1280×720、1440×900、1728×1080，每阶段都要跑 `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`，并检查控制台。

### 前提：先提交现有改动

阶段 0～4 约 175 个文件还未提交。建议先提交，否则这轮改动会和前面的内容混在一起，难以审查和回退。**这一步需要你确认。**

### 阶段 A：对话布局和滚动

改动：3.1 全部；去掉卡片内层滚动和多余留白；卡片铺满栏宽；按消息实际日期分组。

通过标准：
- 主区域的左右边距、标题栏、输入区、卡片上方都能滚动，滚动条贴最右。
- 持续滚动时提示条切换 0 次，来回穿过临界位置时只切换一次，页面高度和输入框位置不变。
- 展开的卡片按钮下方无额外空白，任何视口下卡片标题都不被遮挡。
- 键盘能滚动；“回到最新”出现时输入框位置不变。

### 阶段 B：小练习三种形态

改动：3.2 全部；修正“为什么？”内容和面板错误文案。

通过标准：
- 答到一半，在三种形态间任意切换（6 种方向都测），选择都保留，页面上始终只有一个实例。
- 过渡有连续动画，中间帧能测到位置变化；开启“减少动态效果”时无动画。
- Esc、点遮罩都回到进入前的形态，焦点回到原来的按钮。刷新后恢复沉浸形态。
- 做完后卡片收成一行，结果卡和小结只有一份。
- 从课程页、记录页打开 `/learn/micro/:id` 仍正常，行动执行不受影响。

### 阶段 C：回复过程

改动：3.4 全部。

通过标准：
- 发送后用户消息定位到标题栏下方，回复过程中和结束时都没有大幅跳动。
- 回复中向上滚动不会被拉回。
- 真实模型下点停止：停止生成，已生成内容保留，刷新后仍在，不自动重试。
- 回复中输入的草稿不丢失。

### 阶段 D：对话记录和“我的”

改动：3.3 全部。

通过标准：
- 超过 50 条时也能找到所有对话；搜索、重命名、删除可用，RLS 下不能操作别人的对话（单元测试加真实账号验证）。
- 生成过个人课程的对话不能删，提示清楚，课程不受影响。
- 删除当前对话后，自动切到合理的状态，不留空白页。
- 1280 宽时打开右侧面板，对话宽度不少于 640px，关闭后记录栏恢复。
- “我的”不含对话列表，条目都能进入对应对象。
- 重新登录后直接看到上次对话，只有一个下一步。

### 阶段 E：连续路线

改动：3.5 全部。

通过标准：
- 首页和课程页都显示所有章节，一条路走到底，没有折叠行。
- 打开时定位到当前步骤，顶部的章节和进度随滚动更新。
- 选中其他节点时，节点位置不变。
- 侧边和整页可切换；整页时鼠标在课程卡上也能滚动路线。
- 最长的真实课程（约 117 个要点）滚动流畅，不加载 three.js。
- 课程树视图不受影响。

### 阶段 F：整体验收

从注册开始走一遍完整主线，覆盖上面所有路径，然后你在 Mac 触控板上试手感。通过后回到主线计划的阶段 5。

把滚动、形态切换和答案保留写成 `tests/browser/` 下的回归模块，沿用现有方式：模块接收调用者准备好的页面，不增加 `@playwright/test` 依赖。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 移动挂载容器后，H5P 等嵌入内容重新加载 | 阶段 B 单独测 H5P 步骤；有问题时，这类步骤切换前提示，或保持原位不移动 |
| 对话跨会话切换时，运行中的小练习归属混乱 | 切换会话时，对话内形态收起并保留进度；侧边和沉浸不受影响 |
| 章节全部展开后页面很长 | 打开时定位到当前步骤；顶部显示当前章；实测约 100 个节点 |
| 中断流后落库不完整 | 阶段 C 先做验证，不通过就只在前端停止显示，并如实告诉你 |
| 删除对话被其他数据引用 | 已确认个人课程的引用会阻止删除，按 3.3 提示；阶段 D 开始前再核对一遍其余外键 |
| 单个对话超过 200 条消息时，更早的内容读不到（接口上限） | 本方案不改；真实长对话出现时再加“加载更早消息” |
| 手感只有在真实设备上才准 | 阶段 F 由你在触控板上确认 |

## 7. 不在本方案内

- 动手任务面板的形态切换：原型没有覆盖，继续沿用右侧面板和整页。
- 课程树、3D 视图的改动。
- 移动端适配。
- 按消息内容搜索对话。

# 工作流

> 由 AGENTS.md 拆出。修改本领域代码前必须阅读本文件；与 AGENTS.md 冲突时以 AGENTS.md 为准。

## Workflow Module Boundaries

- Workflow uses one V2 Definition, API repository, server-side LangGraph execution boundary and React Flow editor. Legacy editor/simulation/persistence/migration paths MUST NOT be reintroduced.
- Pure Workflow types, factories and graph operations live under `src/features/workflow/domain/v2` and MUST NOT depend on React, browser storage, Demo fixtures, `src/app` or application singletons.
- Workflow Editor and presentation state belong to the Workflow Feature. App owns assembly and navigation only.
- Production definitions and Runs use authenticated APIs. Removed Legacy browser storage keys MUST NOT become authority or compatibility fallback.
- Course starting templates are database content attached to the Course; the repository holds none, and nothing falls back to bundled templates.
- Ordinary environment variables, State and managed credentials remain distinct. Variable Bindings are structural; Runs freeze ordinary variable values/configuration revisions at launch while server authorization/revocation is revalidated.
- Node tests reuse the actual execution boundary with isolated test State and MUST NOT create formal Runs, progress, completion or mastery evidence. External writes require explicit test confirmation.
- Course integration belongs to the application/API boundary. Run metadata freezes validated `courseId`, `assignmentId` and `workflowTemplateId`.
- A Workflow created from a practice is a normal work owned by the learner and linked to that practice (link stored at the application/API boundary, never inside the Workflow Definition). Practice submission references a frozen Workflow version; trial runs inside the editor do not need to be launched from the practice. Runtime MUST NOT receive or infer Course/Assignment entities. Live success MUST NOT automatically complete an Assignment or grant mastery.
- History viewing is read-only and MUST NOT replace the editing draft. Execution details use Run/Step/invocation/attempt identity. Presentation changes MUST NOT re-fit or relayout the canvas.
- Exported configuration MUST NOT be presented as a standalone executable package unless that packaging capability actually exists.
- Managed connections keep a stable reference while display-name and model edits publish immutable versions. Every definition save MUST, after acquiring the connection-lifecycle lock, resolve its recursive user `p4` provider/tool/allowed-tool references against the owner, selected environment and exact version; platform references and empty draft fields stay untouched. Deletion MUST recheck current references, nested subgraphs and unfinished/waiting Runs inside the database transaction that removes every version and managed credential; an API preflight alone is never authority. Historical revisions do not permanently block deletion, but restoring one MUST revalidate its connections. Restoring a disabled connection publishes a new active version and does not silently re-enable old pinned bindings; users reselect the new version. Registered functions follow the same physical-deletion discipline across all immutable versions, including node references, error handlers and nested subgraphs; the deleting transaction rejects current references and unfinished Runs rather than relying on the browser scan.
- Fixed Workflow references pin one exact `(workflowId, revision)` and remain ordinary `core.subgraph` nodes. Every save MUST validate the complete reachable fixed-revision closure from the Definition itself - owner, existence, unarchived target, exact revision and input/output mapping - and MUST NOT treat a missing transitive target as a leaf or trust the derived index after its target FK cascade. A Workflow MUST NOT be deleted or archived while any unarchived Workflow's current revision can reach it through that closure; dependencies reachable only from historical revisions do not permanently block. `referenced-by`/`delete-impact` MUST report the blocking chain but remain previews; the database transaction rechecks the same closure under the reference lifecycle lock. A reference node MUST NOT enter embedded subgraph navigation. Execution resolves the complete reachable fixed-revision closure on the server at validate, run and node-test boundaries, freezes each target Definition/revision/environment in the Run snapshot and revalidates owner/target-environment/credential revocation on resume; browser-supplied resolved Definitions are never authority. Child State is independent and per-invocation, parent output is received only through explicit `writes`, and every child invocation independently meters its own compute time/nodes/tools while remaining bounded by every ancestor and the root; parent used counters never seed a new child. Every checkpoint written by a descendant MUST persist each ancestor scope's used time/nodes/tools; resume reads the latest reliable snapshot for the invocation chain, merges parallel-branch counters monotonically instead of trusting only the ancestor's last own checkpoint, and excludes human wait. Consumption after an ancestor's last completed checkpoint (including the interrupted node's time/tools/nodes) MUST remain recoverable at the wait checkpoint. A fixed reference is an independent boundary: its root nodes cannot issue parent Commands, while embedded subgraphs inside the target retain ordinary parent-command behavior. Connection/function resource scans, definition save validation and deletion transactions include the current-root reachable fixed-revision closure, and unfinished Runs keep the resources frozen in their closure protected. Reference selection, exact-revision configuration, interface mapping and opening the target in its own editor are implemented; complete reference upgrade UI remains later UI work. Opening a fixed reference must default to its pinned revision, keep an older pinned revision read-only with an explicit latest-version entry, and never write a parent identity into the target Workflow or auto-upgrade the caller.

## Workflow Run Invariants

- Model nodes MAY set a positive integer `modelParameters.maxOutputTokens`. When omitted, the executor MUST omit the provider request's output limit parameter. Legacy `policy.maxOutputTokens` is accepted for saved definitions and history and does not limit a model request.

- Parent/child Run history MUST read each fixed reference's exact frozen target Definition, revision and environment from that Run's snapshot; it MUST NOT resolve the target current head. Child invocations remain grouped by the actual call path, checkpoint namespace and call task, and a referenced Workflow MUST NOT create an independent Run history entry.
- WorkflowTemplate is reusable. A Workflow run launched from a Course Assignment MUST preserve `courseId`, `assignmentId`, and `workflowTemplateId`.
- Two Assignments sharing one WorkflowTemplate MUST remain distinguishable in Run History and completion updates.
- Evaluation output is runtime/evidence data, not CourseAssignment or WorkflowTemplate definition data.

# 前端界面与外壳

> 由 AGENTS.md 拆出。修改本领域代码前必须阅读本文件；与 AGENTS.md 冲突时以 AGENTS.md 为准。

## Product Chrome

- The primary chrome is a left vertical navigation rail with the account avatar at the bottom. It is the single primary chrome. A page title, contextual control, or workspace tool MUST NOT introduce a second full-width fixed header.
- The learner rail grows from real learning state: 首页 by default, then 作品 after a real task/attempt, 记录 after a learning record, and 地图 after the first segment is complete. It is derived, never a level or unlock record. Teachers and admins always receive their full set. Hidden is not locked: URL, ⌘K and the Assistant still reach every destination.
- Content and management pages use headings in normal document flow; graph, canvas, and reader pages use only lightweight contextual overlays so their primary workspace remains dominant.
- Micro Learning is interaction-first. Assistant help may be contextual, but product chrome and Assistant actions MUST NOT visually or behaviorally dominate the assessment.

## New UI Shell (2026-10-30)

- Single design source: `docs/design/new-ui/system/tokens.css` (six type sizes 12/13/14/16/20/28, semantic colors, radii, spacing, three shadows, two glass materials `lg-regular`/`lg-clear`, motion tokens). New styles use tokens only; legacy styles are removed page by page as pages migrate.
- Glass MUST degrade to blur-only on Safari and to opaque surfaces under `prefers-reduced-transparency`.
- Motion: durations 160/240/400/600 ms and three easings; 600 ms only for scene transitions (Archive → course immersive, 3D → 2D flatten). Every transition is reversible and has a `prefers-reduced-motion` alternative.
- The avatar opens the account menu (first row: 打开我的面板). The 我的 panel opens from the Home top-right toggle and pushes, not covers, the conversation.
- Objects open through one Object Shell with four sizes (card S, card L, side panel, immersive). Expanding never slides a new drawer in from the screen edge; entering a course zooms in place and morphs existing overlays. When one object changes size it stays one mounted instance with its state and moves from where it was; it MUST NOT open a second instance of the same object.
- Conversation layout: the Home scroller fills the main area with its scrollbar at the right edge, so scrolling works anywhere in that area; content sits on a centered 760 column. The composer and the title bar stick inside the scroller. Showing or hiding the jump-to-latest control or an object context tag MUST NOT change the scroll range or the composer position.
- Conversation cards span the conversation column and share its left edge with answer text and event rows. Cards do not nest their own scroll container inside the conversation.
- Assistant answer cards are part of the answer, not page state. Text, tool progress and cards keep the message's real `parts` order; nothing written before a tool is discarded. The model decides whether a card is useful and there is no fixed per-answer count. Cards never disappear, merge, collapse or move because learning state changes; the same object updates in place. A completed 小练习 keeps its card and shows its real step list with green checks instead of a separate completion page. Page state MUST NOT append cards to the timeline tail, and opening, starting, submitting or completing an object MUST NOT append an operation message.
- Retired surfaces: Course Center, Explore page and Assistant Messages page; their routes redirect to Archive / Home.

## Archive Chrome (2026-10-31)

- Top-left people bar: `[people icon] | [me] [followed people…] [+]`. The people icon toggles the 人与分享 panel (followed people, profile visibility, revocable share link). Clicking a person's avatar opens that person's panel and applies person focus; clicking it again, blank space or Esc clears both; Shift-click adds a person for comparison.
- Panels change only by explicit user action: they never open, close, shrink or swap content because of zoom, camera, focus or course selection. Every panel has a collapse control that leaves a small strip to reopen it. While a panel is open, scene framing (e.g. the Archive course plane) fits the remaining free area.
- Bottom-right holds only zoom out, a monotonic zoom percentage, zoom in and reset view; bottom-left shows the current map level (领域 / 主题 / 知识). There is no locate-me button and no own-subset highlight toggle.

## Conversation Mainline (2026-11-08)

- Home has two derived states: 首次 (no conversation, no learning record) and 对话 (everything else). The first state is one open question, the composer and database-configured examples; it MUST NOT show a half-screen Course recommendation card. A returning learner lands directly in their last conversation, so no welcome page hides the history; with learning records but no conversation they get a new conversation. Starting a conversation removes overview cards from the conversation space.
- Conversation history lives in a collapsible column on the left of Home: new conversation, title search, date groups, rename, delete, and load more beyond one page. It collapses by itself when a right panel leaves the conversation under 640px and returns when the panel closes; an explicit collapse by the learner stays collapsed. Deleting asks for confirmation. A conversation that created a personal Course cannot be deleted; say so and keep rename.
- The server Navigation decision is the reference for teaching order, not a fixed UI strip or the model's only permitted suggestion. The Home header, 我的, route panel and practice result read the same decision; the Assistant may combine it with the conversation but MUST NOT invent progress or mark unlearned content learned. There is no fixed next-step strip and no template completion reply.
- Database-configured fresh-state examples are ordinary messages sent to the model; there is no deterministic button action reply or route-card template. Without configuration the examples are absent and Home still works.
- A route card shows only the first segment (Micro up to the first Assignment). "查看完整路线" opens a Home side panel that reuses the shared route component for any specified Course and loads no 3D; the panel's 立体视图 opens the Course tree and its 进入课程 action opens that Course page. It shows every chapter on one continuous road, opens at the current step, fits the panel width without clipping or horizontal scrolling, and can switch between side panel and full page without remounting, moving from where it was.
- Simple 小练习 opens in the conversation card; a 动手任务 opens the right panel. Focused immersive 小练习 is a user action, never the automatic continuation. On Home a running 小练习 can switch at any time between in-conversation, side and immersive forms without losing unsubmitted answers; immersive is a modal over the conversation and exits back to the form it came from. The URL records the form and the owning conversation card, so a reload restores the same card/panel/dialog. `/learn/micro/:id` remains the direct-link page for other surfaces.
- A 小地图 answer card draws one Knowledge node's real neighboring edges from the shared graph with a deterministic layout and opens the Archive focused on that node. A 知识点 answer card uses the Archive node representation (title, icon/dot, `knowledgeStateLabel`) and opens `ArchiveNodePanel` in the Home right panel without leaving the conversation; neither card starts a 小练习 or writes progress.
- 我的 is a read-only personal overview: every current unfinished Course, real task states and recent learning, each opening its object. It holds no conversation list. Each Course row MUST show the route's next step before secondary progress details, and MUST NOT add a separate next-step strip. It MUST NOT show task-only "0% 已完成" as Course progress. Course progress is shown as learned points / total points and stays distinct from mastery.
- A newly appearing rail item uses a short, non-blocking transition and respects `prefers-reduced-motion`.
- Objects open from their own card (or My/route row) through the Object Shell and expand in place into the right panel; closing contracts back to the same origin. Card and panel show the same object icon, title and status. The open object highlights its card, switching objects moves the highlight, and closing clears it.
- The composer shows the open object as a context tag. `×` removes only that identity from the next server request and keeps the panel open; acting on the panel again restores it. Opening an object from 我的 or the route panel MUST NOT add a conversation message.
- 我的, the task panel and task cards read the same live Assignment/Course state and update in place after a submit; 我的 lists only tasks that need learner action: in progress, needs revision, awaiting evaluation, and each current Course's next route Assignment. It MUST NOT list untouched not-started tasks that are not the route's next Assignment. Recent-learning rows open their object, and a completed 小练习 shows its real step list in every form with a green check on learned steps; review never records progress. The card the learner clicked owns the runner, including a route card; a second card for the same path does not steal it.
- A mistaken direct submit can be withdrawn from the task panel's submission history or by asking the Assistant. The Attempt stays in history marked 「已撤回」; the task card, panel and 我的 update in place, and no operation message is added. 我的 spans the learner's current Courses: 当前课程 lists every active unfinished Course, while 任务状态 lists only tasks that need learner action across those Courses. The task list is ordered by urgency (needs revision > in progress > route next Assignment > awaiting evaluation), then by latest update; it MUST NOT be sorted by title pinyin.
- The composer accepts `.txt`/`.md`/`.csv` files via `+`, drop or paste and links via `+`; attachments are removable before send and are validated server-side. `@` mentions tasks, Courses, Knowledge and Materials as removable context; `/` runs a common phrase or adds context. Both only supplement the model and never trigger a fixed workflow.
- Completed tool calls render as one collapsible progress line, e.g. 「读取任务要求」. Follow-ups are model-chosen chips (0–3) after an answer; clicking one only fills the composer, newline-appended to an existing draft with the cursor at the end, and never sends. No fixed strip returns. Every write tool renders the same one-line result row from structured output, including failures. An unanswered failed question followed by another question gets one grey 「没有回复」 line.

## Feature Preview

- A feature whose backend is not available MAY ship as a Feature Preview: the real UI and interactions fed by a fixed sample dataset, so users see the intended product.
- Sample datasets live under `src/demo/preview/` and are injected by `src/app` through the same contracts as real repositories.
- Preview regions MUST carry a visible "预览 · 示例数据" marker, use obviously sample identities, never mix with real user data and never write durable state. Replacing a preview with the real backend only swaps the injected source.

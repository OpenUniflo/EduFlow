## 0. 结论

- 下一轮 **P0 只做“环境 + 能力配置”**，不做画布样式细节。环境问题不是样式问题，而是四件事：**授权可见性、连接→节点闭环、Hosted 真实调用、授权运维**。
- “每个账号能不能自己维护模型/工具”在代码层已经有基础：用户创建的连接会按 owner 注入环境，模型/工具/连接器都能被节点使用；缺的是**刷新、轮换、标识和诊断**，不是从零造一套能力层。
- 画布本地项（运行 tab 重复入口、窄屏/右栏、键盘、同名归属、历史分支）降为 **P1/P2**。
- 会话摘要里被列为“待确认”的 required/optional 语义，**实际已于 2026-10-21 冻结为 A 并已实现**（计划第 8 节）。本计划不重开；要改 B 必须新增变更记录，不能当普通优化做。

## 2. P0：环境与能力配置（下一轮主线）

### P0-1 环境不可用要能自诊断（含移动端位置）

**现象**：当前测试管理员是**手工加入 `ownerIds`** 后才看到环境；任何新账号或团队成员（以及 D3 移除授权之后）打开画布，仍只会看到“没有可用环境，请检查环境与连接。”，无法判断是未授权、服务异常还是加载失败；移动端提示还会与组件库/历史条重叠。

**目标**：三种状态文案不同，并能直接给出下一步动作。

**改动**：

1. 增加纯函数 `environmentAvailability({ initialLoadStatus, items, error })` → `loading | unavailable | error`，由编辑器统一渲染，不在 JSX 里散落判断。
2. `unavailable` 态展示：可能原因（管理员未授权 / 服务未配置环境）、当前账号 UUID 与复制按钮（来自已有 `ownerId`）、`重新加载环境`、管理员授权指引；`error` 态展示错误类别与 requestId（可得时）。
3. 位置：桌面保持右上（`top:64px`）；`<=900px` 移到**画布顶部状态条插槽**，与 palette、历史条、图说明共用同一套偏移，不再各自写 `top:112px`。
4. 安全边界：只显示当前账号自身 UUID，不显示环境配置、其他 owner 或凭据。

**验收**：

- 390 / 768 / 1024 下提示与 palette、历史条、图说明、执行气泡都不重叠（几何断言 + 截图）。
- 三态文案互不相同；不再用一句话覆盖所有原因。
- 单元测试覆盖分类函数；SSR 测试覆盖三态渲染；复制按钮有可访问名称。
- 无环境时不阻塞画布编辑与保存。

**估**：0.5–1 天。

### P0-2 连接 → 节点闭环（用户能自己配好并跑起来）

已具备：创建连接、加密凭据、测试、停用、按 owner 注入环境。缺的是下面四个断点，按影响排序：

1. **保存连接后工具不刷新**：连接保存后同时刷新环境与工具（新增 `refreshTools()`，在 `onSaved` 调用），保证新 HTTP/MCP 工具立即可选。
2. **轮换版本后节点不会自动跟随**：版本不可变而引用键含版本；旧版本在停用/移除前仍可用，但停用旧版会让已配置节点失联。需要“可升级提示 + 受影响节点发现 + 一键更新到最新版本”，并在 `preflight` 阶段生成可定位诊断，而不是只在运行时失败。若产品选择更强方案，见决策 D2。
3. **模型连接标识错误且轮换后无法区分**：环境面板把所有 provider 标成“执行端管理凭据”；旧版本连接未停用时会与新版本同时出现在下拉里，名称相同、只能靠 `p4:...` 引用区分。需要显示“我的连接 · 版本 N”，默认只呈现最新可用版本，并保留只读/写入与凭据状态。
4. **节点内跳转不回流（可选）**：从模型节点进入“管理环境与连接”，保存后返回节点并自动选中新连接；时间不足可只做提示。

**验收**：

- 新建 HTTP 连接后，**无需刷新页面**即可在工具节点选中并运行（Local）。
- DeepSeek `v1 → v2` 轮换后：旧节点默认仍可用但提示“有新版本可更新”，一键更新后 preflight 通过；停用 v1 后未更新的节点在 preflight 明确列出并给出修复入口。
- 环境面板对用户连接显示“我的连接 · vN”，对环境内置显示“执行端管理凭据”；模型节点下拉不再出现两个同名同款的连接选项。
- 单测：工具刷新、受影响节点发现、preflight 诊断；API/控制台无新增错误。

**估**：1.5–2.5 天。

### P0-3 Hosted 真实模型/工具调用验收

**现状**：Hosted 只跑过 `入口 → 结束`（2 节点），DeepSeek、DeepWiki、GitHub 工具都未真实调用；这不代表环境可用。

**要做**：

- `开始 → DeepSeek 模型节点 → 结束`：验证凭据、流式输出、错误分类、token/费用；
- `开始 → 只读工具节点（DeepWiki）→ 结束`：验证连接发现、工具目录、只读副作用、超时；
- 至少保留一条失败路径（如无效凭据或超时）的错误分类证据。

**验收**：两条 Run 成功 + 一条失败路径可读；记录 Run/Thread/环境修订身份；证据写入 `docs/acceptance/`，不写凭据；模型调用费用由你确认上限。

**估**：0.5–1 天（含费用与限流等待）。

### P0-4 授权与运维生命周期

- `ownerIds` 变更 runbook：谁授权、变更前备份、如何回滚、变更后重部署 `edu-flow-workflow`。
- 环境 JSON 的**脱敏结构备份**（owner/provider/tool/limits 结构，不含密钥），用于回滚与审计。
- Workflow 服务由 Git/CI 部署，不再从本地工作区直接推生产（此前已发生一次）。
- 测试管理员处置见决策 D3。

**估**：0.5 天 + 决策。

## 6. 下一轮执行顺序（单写作者）

1. **Round A（环境可诊断）**：P0-1 + 三态/几何证据。
2. **Round B（连接闭环）**：P0-2 的 1/3 先做，然后 2（受影响节点 + preflight 诊断）。

## 8. 风险

- 环境仍是管理员预设：用户无法自助开通，支持成本转移到管理员；若不自建 provisioning UI，需要明确“谁负责授权”。
- D2 选 C 会改持久身份与运行兼容性，风险高，不建议与本轮混做。
- 真实模型调用有费用、限流与凭据风险；必须先定费用上限和测试流程。
- 移动端插槽重构会动 palette、历史条、图说明的现有位置，需要回归，不能只修提示。
